Sixteen agents, one click from the chat

Deckhand is a Claude Code mod: a deck of reusable agents beside the chat. Make an agent once, use it in any project, and keep it inside the limits you set. Version 0.2 fills every deck with built-in agents, shows what each running agent costs, and can put several agents on one task.

Install from a Claude Code terminal session

/plugin install deckhand --marketplace EJhayGit/deckhand

Answer y to add the marketplace, then pick a scope. In the desktop app, click + next to the prompt box, then Plugins, Add marketplace with EJhayGit/deckhand, then Add plugin. A Deck panel opens beside the chat.

The built-in deck

Every deck now starts with these 16. Click Use on a card and its instructions, model and effort apply to the chat. Click a group's name to fold it.

Core

8 agents
  • reviewercareful Sonnet · high

    Reviews code or a diff for real bugs and risks, most serious first. Changes nothing.

  • bug-fixermedium Sonnet · medium

    Finds the root cause of the bug you describe and fixes it with the smallest change.

  • test-runnerlight Haiku · low

    Runs the tests and reports what failed and the likely cause. Changes nothing.

  • test-writermedium Sonnet · medium

    Writes focused tests for new or untested behavior, in the style the project already uses.

  • docs-writerlight Haiku · low

    Writes and updates docs in plain words. Touches only documentation.

  • plannercareful Opus · high

    Turns a feature request into a short, ordered plan with files, risks and checks. Writes no code.

  • researchermedium Sonnet · medium

    Researches a question on the web and in the code, and answers with dated sources.

  • refactorermedium Sonnet · medium

    Simplifies code without changing what it does, with tests run before and after.

Design

3 agents
  • frontend-designercareful Opus · high

    Designs and builds distinctive web pages and app screens that do not look generated. Uses taste-skill.

  • ui-criticcareful Sonnet · high

    Critiques a screen or page for hierarchy, spacing, contrast and the generated look. Changes nothing. Uses taste-skill.

  • graphics-designermedium Sonnet · medium

    Makes launch graphics, icons, social and OG images, and color themes as SVG or code.

Security

3 agents
  • security-auditorheavy Opus · xhigh

    Audits the codebase for exploitable security bugs and verifies each finding. Changes nothing. Uses Trail of Bits skills.

  • dependency-auditorcareful Sonnet · high

    Audits dependencies for known vulnerabilities, risky packages and lockfile problems. Uses Trail of Bits skills.

  • change-security-reviewcareful Sonnet · high

    Reviews the current branch or a diff for security regressions before it merges. Uses Trail of Bits skills.

Web

1 agent
  • website-reviewercareful Sonnet · high

    Reviews a live website for speed, accessibility, SEO, broken links, console errors and mobile layout. Give it a URL. Uses Playwright or Chrome DevTools.

Lead

1 agent
  • swarm-leadcareful Opus · high

    Splits a big task into parts, hands each to the best deck agent in parallel, then checks and merges the results.

What's new in 0.2

The deck, the limits and the chip band work as they did in 0.1. These are the additions.

Built-in agents
Sixteen agents in foldable groups: Core, Design, Security, Web and Lead. The old starters have new, fuller instructions.
A file in .claude/agents/ with the same name replaces the built-in card.
Set up
Some agents work best with a plugin, and their cards say needs …. Click Set up, then Add: Deckhand adds the plugins to this project's .claude/settings.json, and Claude Code offers to install them when you restart it.
Nothing global is changed.
Runs
The Runs tab shows every agent this session started, from a swarm or from Claude: its model and effort, steps, context use, tokens, estimated cost, time and a progress bar, with totals on top.
Cost is an estimate from list prices.
Swarms
Parallel: pick a preset (Launch kit, Security sweep, Ship check) or tick agents, type the task, and click Start. Lead: swarm-lead takes the task, splits it, and hands parts to the deck's agents.
Optional. From the prompt: /deck swarm launch-kit <task> or /deck swarm lead <task>.
Cards and effort
A new card look with a pixel mascot, a colored weight word, and the model and effort. An XHigh chip joins the effort choices.

Launch plan

One page for launch day. The targets are left open on purpose: Deckhand collects no usage data, so the first week sets the baseline.

Goal

Get Claude Code users to install 0.2 and put a built-in agent to work on a real task in their own project, in the first session.

Audience

  • Claude Code users who already keep agents in .claude/agents/ and want them one click away, with limits they can see.
  • People who want a reviewer, planner or test runner without writing one first.
  • Users of taste-skill and Trail of Bits skills, whose plugins the Design and Security agents set up.

Channels

  • The GitHub repo: README, a 0.2.0 release built from the changelog, and this page.
  • The marketplace itself, EJhayGit/deckhand, which is where installs happen.
  • One social post with the OG card and a short screen recording of the Deck, a swarm and the Runs tab.
  • Claude Code community spaces where people share plugins.
  • A note to the taste-skill and Trail of Bits skills maintainers that Set up points at their plugins.

Launch day

  1. Add a LICENSE file, then tag v0.2.0 and publish the 0.2.0 GitHub release with the changelog text.
  2. In a clean project, install with the line above in a terminal session, then again through the desktop app. Click Use on one agent from each group and run Set up once.
  3. Publish this page with the OG card and icon from launch/graphics/. Export the OG card as a PNG at a full web address first: most social sites don't show SVG share images.
  4. Record the Deck, a Parallel swarm and the Runs tab, then post it with the install line.
  5. Share in community spaces and send the maintainer notes.
  6. Stay on GitHub issues and the post replies for the rest of the day. Fix install blockers first.

What to measure

  • Repo views, unique visitors and clones, from GitHub's Insights, Traffic page.
  • New stars and forks in the first week.
  • Issues opened, sorted into install problems, bugs and requests.
  • Which built-in agents people name in issues and replies.
  • Questions about Set up, swarms and the cost estimate: each one points at a doc to fix.
  • Replies and shares on the launch post.

Write the first-week numbers into docs/handoff.md so 0.3 has something to compare against.
